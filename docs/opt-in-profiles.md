# Opt-in profiles, registry labels and strict JSON

Status: all contracts named here are `0.1.0-draft` and unfrozen. Nothing on this page is default behaviour. Each profile is selected only by a host-governed field of `RuntimeAuthorityProfile` (or a rule-revision profile passed to the workflow); with the field unset the module does not run, the field is omitted from profile dumps, and no stored or hashed byte changes. The pinned default path and the default `acp run` examples are unchanged. Nothing here is published, released or selected by the hub lock.

Read each module's docstring for the full limits. Common to all of them: the record store is a plain JSON file under a same-host lock with no keyed integrity check, so the rows give visibility to an honest reader, not tamper evidence, and `signer`, `issuer` and similar members are asserted names.

## Profiles

| Profile | Selected by | What it adds | Main limit |
|---|---|---|---|
| `operation-identity/0.1` (`operation_identity.py`) | `RuntimeAuthorityProfile.operation_identity` | An `operation_id` supplied by the grant issuer inside the approved `runtime_authority` extension, stable across grant revisions; one join row per attempt; the journal `check_id` carried by check events, resolution checks and the join row; issuer-only renewal (any other writer is refused and recorded); `merged_into` as a field. Without it `effect_id` keeps its legacy meaning (`commitment({proposal, grant_id, grant_revision})`, so renewal changes it). | Defined over the control plane's own rows; says nothing about whether a destination committed one effect per operation. |
| `rule-revision/0.1` (`rule_revision.py`, `docs/rule-revision-profile.md`) | a `RuleRevisionProfile` passed to `BoundedAuthorizationWorkflow(rule_revision_profile=...)` | Digest-pinned rules and append-only revision rows for four kinds (reason registry, policy, gate implementation, merge equivalence rule); a digest counts as adopted only when a configured signer other than the reviser signed it; `rule_identity` on decision and refusal rows; trend flags, declared against measured arity, recomputability helpers. | Trust moves to the revision signer; it is not removed. |
| `freshness/0.1` (`freshness.py`) | `RuntimeAuthorityProfile.freshness` | Three named clocks (`evaluated_at`, `recorded_at`, `observed_at`); a check deadline fixed at opening; an `overdue` state and a reaper; a clock re-read immediately before `destination.apply` (`check_expired_before_dispatch`); a recorded age basis (`nonce_bound` or `source_asserted`); authorised, signed age extensions. A reaper failure fails closed. | The pre-dispatch re-read narrows the check-to-commit window and does not close it; status age at dispatch can reach twice the class bound (pinned by a test); the lease is a same-host `flock`. |
| `witness-digest/0.1` (`witness.py`, `acp witness digest|publish|verify`) | called by a host; no profile field | A hash chain over the rows of every list-valued ledger of a record document, a witness record (per-ledger `{count, head}`, `sequence`, `previous_digest`, `digest`), a `Witness` protocol and an append-only local file witness. | Visibility for a reader who holds the digest, not protection against the witness holder; rows after the latest digest are unwitnessed; scalars and dictionaries (and the destination snapshot) are not covered. |
| `holder-inventory/0.1` (`holder_inventory.py`) | `RuntimeAuthorityProfile.holder_inventory` with `ActionClass.requires_revocation_assurance` | A flagged action class holds (`holder_inventory_missing`) until an inventory that enumerates at least one holder and names who recorded it exists; `classify_holders` reports witnessed refusals and `coverage_unknown` holders, never "expired". | An inventory is a claim by its writer; a holder nobody listed stays invisible. |
| `merge-record/0.1` (`merge.py`) | `RuntimeAuthorityProfile.merge`; needs `operation_identity` | A merge record over operation ids only: survivor and folded operations, equivalence rule identified by a digest adopted by a signed `merge_equivalence_rule` revision; unadopted rule is `unknown`, an unfunded authority is `held`, malformed or already-folded ids are `refused`; only `merged` has effect (one shared effect budget; second effect suppressed with `operation_merged_effect_exists`); a compensation obligation is a record only. | Trust moves to the merge authority and the rule signer; nothing is compensated or reversed here. |
| `reversibility/0.1` (`reversibility.py`) | `RuntimeAuthorityProfile.reversibility`; action-class member `x-reversibility` | `irreversible`, `reversible_until` or `reversible_at_cost` on the action class (the legacy `irreversible` boolean stays derived); a cached "open" purpose snapshot accepted only for a reversible class within its age bound and while no recorded closure exists, each use appended as a `snapshot_use` row. Without the profile a purpose outage refuses for every class. | `reversible_until` and `reversal_cost` are producer assertions; the cache cannot be shown to be authentic. |
| `dedupe-ttl/0.1` (`dedupe.py`) | `RuntimeAuthorityProfile.dedupe`; needs `operation_identity` | `provider_horizon_seconds <= escalation_deadline_seconds < dedupe_ttl_seconds`; a destination declares `dedupe-ttl/0.1` and its TTL (never inferred); an unresolved attempt stays `unknown` through the horizon and escalates once inside the key TTL (`escalation_pass`; later is `escalation_after_key_ttl`); `in_progress` is neither failure nor acknowledgement and mints no new key. | Nothing retries here; key expiry never makes a duplicate fresh; the escalation row is a record only. |

Unset-by-default is enforced for the combinations too: `merge` and `dedupe` without `operation_identity`, and action-class `reversibility` values without the `reversibility` profile, are refused when the profile is built.

The optional ODES contract drafts for these profiles live in `cogno-us/open-decision-evidence-standard` (`contracts/operation-identity`, `rule-revision`, `freshness-clocks`, `witness-digest`, `holder-inventory`, `effect-reversibility`); none is frozen. Merge-record and dedupe-ttl have no ODES contract draft.

## Reason registry labels

There are two registry files. `schemas/runtime_authority_reasons_0_1.json` is the original 121 codes (120 `typed_only`, 1 `recomputable`), byte-identical to its pinned form. `schemas/runtime_authority_reasons_0_2.json` is the full set of 157 codes: the 0.1 entries unchanged plus the codes the opt-in profiles emit. A decision, refusal or journal row carries label `runtime-authority-reasons/0.1` unless one of its reasons is a code only 0.2 registers (`vocabulary_for` in `runtime_authority.py`), in which case it carries `runtime-authority-reasons/0.2`. 0.2 is a superset, because one row can mix codes and carries one label. Default-path rows keep 0.1.

## Strict JSON

`strict_json.py` reads operator-supplied and stored documents fail closed: input that is not UTF-8, an object with a duplicate member name, and the constants `NaN`, `Infinity` and `-Infinity` are refused with stable codes (`input_not_utf8`, `input_json_duplicate_member`, `input_json_non_finite_number`). Valid input parses to exactly what `json.loads` returns. It applies to the `acp run` input files, the `acp validate-run` and other CLI model loads, the record store loads in `bounded.py` and `persistence.py`, policy configuration files and witness files. It is not a profile and has no switch. `replay.from_json` stays lenient on purpose, because the python-mode dump this project writes can hold `NaN` or `Infinity` in free-form members and a test pins that.
