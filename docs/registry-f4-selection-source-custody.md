# `selection_source` custody requirements (Registry F4 ages-only consumer)

Status: BUILDER_TESTED developer documentation. Non-authorizing. Not independently qualified. Applies to `agent_control_plane.registry_f4_age_governance.GovernedAgeWorkflow`.

## What the Control Plane does and does not do
The workflow calls the host-supplied `selection_source()` four times per authorized effect (construction, `decide`, `execute` entry, and the commit gate immediately before `destination.apply`). Each call must return a `SelectionMaterial(record_text, selection_text, trust)`. Registry (`verify_and_decide_v2`, required participation, exact `Ed25519Verifier`) verifies that material and the workflow compares the result with the values and effective-policy digest bound at construction. The Control Plane keeps NO durable state about selections: no epoch ratchet, no trust-snapshot high-water mark, no revocation list of its own. Everything below is therefore a duty of the host's source, because the Control Plane can only judge what it is given.

## Requirements
1. **Freshness.** Every call must read the CURRENT authoritative record, selection envelope and trust snapshot at the moment of the call. No caching across calls, no reuse of material from construction. A source that serves a stale-but-valid copy defeats every later boundary.
2. **Revocation visibility.** The trust snapshot returned must carry the current `revoked_selections`, `revoked_key_ids` and `min_epochs`. A revocation or withdrawal must be visible to the very next call. A source that cannot reach the revocation authority must RAISE (the workflow then refuses, fail closed) rather than return the last known material.
3. **Epoch.** Supersession is recognized only as a changed effective-policy digest (the workflow then refuses with `selection_changed` and the host must rebuild). A replacement selection with a different epoch but the same effective values is accepted, because the effective policy is identical. Registry's `min_epochs` floor in the trust snapshot is the only epoch-rollback control; the source must publish current floors.
4. **Rollback.** The source must be monotonic: it must never serve an older trust snapshot version, an older epoch, or an older record version than it has already served. The Control Plane does NOT detect a source that rolls back to an older, still-unexpired, mutually consistent (record, selection, trust) set that predates a revocation; Registry judges each set on its own. If the source is backed by replicated or restorable storage, rollback protection (a persisted high-water mark, or a signed monotonic counter) belongs in the source or in an Architect-authorized Control Plane mechanism (not built; see options in the increment record).
5. **Authenticity and custody.** The source returns raw text only; the Control Plane trusts nothing in it until Registry verifies the Ed25519 signature against the trust snapshot's issuers and their scope grants. The trust snapshot itself is the trust root and must come from the host's pinned trust-distribution channel, never from the same channel an attacker controlling the record could write.
6. **Scope.** The source must serve the selection for exactly the workflow's scope (consumer, tenant, action/operation, manifest institution and authority domain). Serving another scope's material is refused (`selection_*_mismatch`), but it makes the workflow unusable.
7. **Latency and availability.** The commit gate runs once per effect immediately before dispatch; a slow source lengthens the interval between authorization re-resolution and dispatch, and an unavailable source blocks effects (fail closed). Budget accordingly.
8. **Thread safety.** The source may be called concurrently from multiple `decide`/`execute` calls on one workflow and must be safe for that.

## Residual window (not closed)
The commit gate runs immediately BEFORE the delegated `destination.apply` is entered, not inside the destination's own transaction. A revocation that lands during the delegated call itself is seen only at the next boundary. Closing it requires the destination to expose a transaction hook for a Registry check, which no existing Control Plane interface provides.
