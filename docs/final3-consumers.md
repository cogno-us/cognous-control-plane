## 3. Honest limits and findings

* Unsigned local store, no anti-rollback, host-supplied `legacy_cutoff` (freeze record section 5): unchanged; the binding guards drift, not a store writer.
* The persisted binding carries the EFFECTIVE observation values (frozen contract). A host-value change that leaves every effective value and Registry digest unchanged (host 300 -> 299 under a Registry value of 60) is therefore NOT refused by the binding (`test_b03b`); a change that moves an effective value is. The activation-ledger configuration digest does cover the host values (`test_g01`). The request to "refuse when a host value changes" is met only for host changes that change the effective policy; this follows from the frozen D-06 members and was not worked around.
* The constructor `clock_tolerance_seconds` is untouched, bound for equality only, and not narrowable; the Registry refuses its member name.
* The extreme-tolerance `OverflowError` in protected `bounded.py` (DEF-OBS-TOL-OVERFLOW-1) is a separate defect, out of scope: host tolerances up to 2147483647 are admitted by this consumer, and a host that sets an extreme tolerance still hits that defect at reconcile.
* Lowering the observation values can only add `observation_stale` / `observation_time_future` holds (never a retry, never a pass: `test_b05`).
* The Registry does not check host preconditions; this consumer does (freshness profile present, observation policy present and valid). The commit gate runs immediately before `destination.apply`, not inside the destination's transaction (unchanged).
