## Composed workflow (Work Package B): `GovernedPolicyWorkflow`

The host declares applicability explicitly with `GovernedFamilies(f4_ages=..., class_age=..., class_unreadable=...)`; each declared family carries its `GovernedScope` and `selection_source`. Every declared family is mandatory at construction, decision entry, execute entry and the commit gate; any failure (source error, revoked, withdrawn, expired, changed, out of scope) refuses the whole workflow. There is no fallback to a smaller set and no optional overlay; an undeclared family leaves the host value in force. The scopes must share consumer, tenant and action.

Composition is deterministic: F4 scalars, then class status age over the host profile, then the unreadable value over the age-effective profile. Before use: (1) the ORIGINAL host profile is validated against the existing invariant (an irreversible class that is not `refuse` is `host_class_invalid`, before any source read); (2) the FINAL configuration is validated (`final_composition_defect`): no scalar, class age or unreadable value above the host value, only the governed fields differ, the extension limit cannot grow, and the host invariants still hold (`composed_widens_host`, `composed_profile_invalid`, `host_class_invalid`).

| Item | Where it is bound |
|---|---|
| Class age, class `on_unreadable`, outage-extension limit (profile-bearing) | The FINAL effective `RuntimeAuthorityProfile`: `approval_commitment` hashes `profile.model_dump()` and the same hash is the persisted decision binding's `catalogue_digest`. Issue approvals against `workflow.runtime_authority_profile`. Existing mechanism, unchanged. |
| F4 `status_max_age_seconds`, `approval_max_age_seconds` (constructor scalars, NOT in the profile) | This workflow's own bound identity (compared at every boundary; edits after construction refuse `scalars_modified`; exposed by `registry_governed_policy_identity` with `f4_scalars_in_approval_commitment: false`). NOT in `approval_commitment`, NOT in the persisted decision binding. |

### Unresolved design decision (reported, not decided)

`approval_commitment` does not cover the F4 scalars and the persisted decision binding carries no scalar member. Narrowing them can only make freshness refuse sooner, so a Registry narrowing never widens anything; but a decision persisted under narrowed scalars is executable by a workflow whose scalars are the host's (characterised by `test_i04`; freshness is re-resolved at execute under the executing workflow's own scalars). Binding the scalars into the approval preimage or the decision binding is an authority-semantic change to a commitment and needs an explicit Architect decision plus F3 requalification. Nothing was invented here and no approval format was created. Options for the decision: (A) accept: scalars are execute-time freshness inputs, bound only per workflow instance; (B) add a scalar member to the persisted decision binding (a new binding member, compatible readers needed); (C) add the scalars to the approval preimage (invalidates every existing approval). Builder recommendation: (A) until a requirement for (B) appears.

**Update (2026-10-29): resolved by D-06 Option B** (Architect-authorized; BUILDER_TESTED, not independently qualified, F3-A pending). The composed `GovernedPolicyWorkflow` now persists `binding.runtime_authority["effective_configuration"]` (carriage C2, a variant of (B) that fails closed for legacy readers) binding the F4 scalars, the other constructor scalars, the ObservationPolicy, both profile digests, the scope and the declared family set; `execute` refuses `authorization_binding_changed` (durable `EffectTimeRefusal`) when the persisted effective-configuration member differs from the live one; the read-only pin-export and claim-issuance paths fail closed without an `EffectTimeRefusal` (see `docs/effective-configuration-binding.md` section 8). `test_i04` was converted in place to its refusing successor form (no `xfail`/`skip`) and is further covered by `test_c03`. (Correction 2026-10-29: the original sentence said `test_i04` was kept as a strict `xfail` and that refusal applied on 'any difference'; the masked-host limit in section 10 of the binding document qualifies the latter.) The approval preimage is unchanged. Contract, legacy rule, limits (unsigned store, no anti-rollback, host-supplied cutoff, mixed fleets): `docs/effective-configuration-binding.md`.

## Deployment applicability (Work Package C)

Target invariant: ONE declared authoritative governed policy configuration per (tenant, action, authority scope) at a time.

Finding: the Control Plane has no supported activation boundary that can enforce it. The only construction site in `src/` is `cli_run.py` (a plain `BoundedAuthorizationWorkflow`, no profile, per-run store); the three governed workflows are never instantiated in `src/`; there is no composition root, host factory or activation record; the manifest has no governance member; `BoundedRecordStore` is a per-run file with no (tenant, action) index; `activation_sequence` is RESERVED (`docs/policy-binding-approval-generation.md`, EXT-S4). Persisted decisions do carry `catalogue_digest` on the runtime-authority path, so a differently configured second workflow is detected at execute only when it shares the record store, the decision came from the profile path, and the issuer committed the effective profile; an F4-only or plain workflow is not visible in stored state.

What is implemented (local, advisory, refuse-only): `GovernedActivationLedger`, an optional host-owned in-process claim table keyed by (tenant, action, institution, authority domain). The configuration identity covers the declared families, operation ids and scope AND the existing bound identity material (host values, each family's Registry effective-policy digest and effective values, the F4 scalars and the final effective-profile digest), so two differently governed configurations cannot share it (correction after review: the first version omitted the effective values). The claim is made only after construction succeeded (a failed construction leaves no claim) and is atomic under the ledger lock. A second workflow with a different configuration identity is refused `conflicting_governed_configuration`; the host replaces a configuration only by `supersede`, after which the old workflow refuses `activation_superseded` at every boundary. It cannot see another process, a plain workflow, or a governed workflow built without the ledger, so this is NOT deployment-wide exclusivity and must not be described as such (`test_l03`).

Missing contract (precise): a host-owned, durable, single-writer binding of (tenant, action, authority scope) to one governing configuration identity, checked at construction, decision and execute. Minimal proposal, no new authority root: define a configuration-identity digest (workflow class, declared families with their Registry effective-policy digests, scope tuple, institution and authority domain); have the host's own `BoundedRecordStore` (or its deployment configuration) record it on first use under the existing record lock and refuse a different digest with a new non-authorizing reason. That needs a record-schema and reason-vocabulary change, which this repository treats as F3 requalification; it is therefore a proposal only. Until then the one-workflow-per-action rule is a host duty enforced by the host's composition root.

## FINAL3 successor: anchor deadline and ObservationPolicy families (Registry `r08-v8`)

BUILDER_TESTED, not independently qualified (F3-A and F3-B independent qualification PENDING); see `docs/final3-consumers.md`. Three new optional slots join `GovernedFamilies`, `FAMILY_NAMES`, `registry_effective_policy.FAMILY_TABLE` (contract `r08-v8`) and `SCHEMA_REVISIONS` (1 each). Each is independent, mandatory when declared, verified at construction, decision entry, execute entry and the pre-dispatch commit gate, and bound by the D-06 binding (`members.families`) and the immutable snapshot. Composition order: the existing order unchanged, then `anchor_deadline`, `observation_max_age`, `observation_clock_tolerance`; `terminal_revocation` stays last. Families that are not declared leave every bound identity, configuration digest, snapshot identity and D-06 binding digest byte-identical (golden-pinned).

The activation-ledger configuration digest additionally covers the HOST anchor flag and HOST observation values (only when a new family is declared); the persisted D-06 binding carries the EFFECTIVE observation values, so a host change fully masked by a narrower Registry value does not change the effective configuration and is accepted by the binding (stated limit, tested).

## Limits (not hidden)

The commit gate runs immediately before `destination.apply` is entered, not inside the destination's transaction (accepted for bounded engineering only; stronger production atomicity is not established). Selection-source custody, freshness, revocation visibility, epoch floors and rollback protection are host duties (`registry-f4-selection-source-custody.md` applies unchanged); there is no Control Plane ratchet. The cached-purpose-snapshot path does not read `on_unreadable` (protected evaluator; not changed). A profile carrying `policy_binding` is refused for the profile-bearing families. No generic policy interpreter, no new authorization or trust authority, and no `r08-v6`.
